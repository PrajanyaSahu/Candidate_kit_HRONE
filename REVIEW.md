# REVIEW.md

Defects found in the starter `app/main.py`, in the order they appear. "Fixed" means the fix is in the submitted `app/main.py`.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` | No `tz_aware=True`, so PyMongo returns naive datetimes. Naive and aware values get mixed (`compute_overtime` subtracts a naive stored `punch_out` from an IST-aware `end`). | Punch-out or any overtime calculation on a stored record raises `TypeError` -> 500. | `tz_aware=True`; every instant is an aware UTC datetime inside the code and converted to epoch ms only at the API boundary. |
| 2 | startup (missing) | No indexes at all, and no uniqueness guarantee. `GET /attendance` and every analytic would be a collection scan on 100k docs. | `explain` shows `COLLSCAN`; slow list at scale. | `ensure_indexes()` in the lifespan hook: unique `emp_code`, unique `(emp_code, date)`, plus the sort/filter indexes listed in DECISIONS.md. Idempotent. |
| 3 | `create_employee` | Check-then-insert (`find_one`, then `insert_one`) with no unique index. | 10 parallel `POST /employees` with the same code -> several 201s and duplicate employees. | Unique index on `emp_code`; `insert_one` and catch `DuplicateKeyError` -> 409. |
| 4 | `create_employee` | `created_at = datetime.now()` is naive *local* time, and it is returned as an ISO string, not epoch ms. | Response `created_at` is a string; value shifts with the server's time zone. | UTC `now_utc()` (ms precision), returned as epoch ms. |
| 5 | `EmployeeIn` | No validation: any `emp_code` format, bad email, `shift_start == shift_end`, `joined_on` of `2026-02-30` or `"hello"`, empty name. | POST those bodies and get 201 instead of 422. | Validators for each rule in the contract (code pattern, email, `HH:MM`, shifts differ, real calendar date, lengths). |
| 6 | `list_employees` | `skip = page * page_size`: page 1 skips the first page. | `GET /employees?page=1` never returns the first 20 employees. | `(page - 1) * page_size`. |
| 7 | `list_employees` | `total` is `count_documents({})`, ignoring the `department` filter. | Filter by department; `total` is the whole company. | `count_documents(q)` with the same filter. |
| 8 | `list_employees` | No sort (unstable paging) and no bounds on `page` / `page_size`. `page=0` gives a negative skip -> PyMongo `ValueError` -> 500. | `?page=0`, `?page_size=100000`. | Sorted by `emp_code`; `page >= 1`, `1 <= page_size <= 100` -> 422 otherwise (R10). |
| 9 | `punch_in` | Unknown employee: `emp` is `None`, then `emp["shift_start"]` raises `TypeError`. | Punch in with `EMP9999` -> 500 (must be 404). | `get_employee_or_404`. |
| 10 | `punch_in` | `datetime.fromtimestamp(ms/1000)` uses the server's local zone, gives a naive value, and keeps fractional seconds (R1 says truncate to whole seconds). `if body.punched_at` also treats `0` as "missing". `ts.date()` is not the IST date. | Punch at 23:30 UTC (05:00 IST next day) gets the wrong `date`; `09:40:00.900` is not truncated. | `ms_to_dt()` = UTC, truncated to seconds. Date from `attendance_date()` (IST, with the overnight rule R1). `is not None` checks. |
| 11 | `PunchInIn` | `punched_at: Optional[int]` accepts seconds-looking values, floats-with-no-fraction and out-of-range numbers; `status` is any string. | `punched_at=1783312500` (seconds) -> 201; `status="ABSENT"` or `"banana"` -> 201. | Strict int with `100000000000 <= x <= 4102444800000`; `status` is `Literal["PRESENT","WFH","ON_DUTY"]`. All give 422. |
| 12 | `punch_in` | Check-then-insert race. | Two parallel identical punch-ins -> two records for one day. | The unique `(emp_code, date)` index decides; the loser gets `DuplicateKeyError` -> 409. |
| 13 | `punch_in` response | Returns `id` (the MongoDB `_id`) and raw datetimes. | Response contains `"id": "..."` and ISO strings. | `serialize_record()`: no `_id`; instants as epoch ms; legacy fields defaulted. |
| 14 | `compute_late_minutes` | (a) Shift start is built from the punch-in's own date and zone (UTC), not IST. (b) Floors to whole minutes *before* comparing, so 09:40:01 (10 min 1 s) becomes 10, which is not `> 10`, giving 0 instead of 10. (c) No overnight handling. | Punch 09:40:01 IST -> `late_minutes` 0 (R2 says 10); a UTC server shifts every value by 5:30. | Anchor shift start on the attendance date in IST; compare the exact seconds to 600; then floor. |
| 15 | `compute_work_hours` | Built-in `round()` on a float: banker's rounding plus binary error. No truncation to seconds. | 29250 s = 8.125 h -> `8.12`; R4 needs `8.13`. | Exact `Decimal(secs)/3600` rounded `ROUND_HALF_UP`. |
| 16 | `compute_overtime` | No 30-minute minimum (R3); overnight shift end is not on the next day; naive/aware mismatch (#1). | Once the `TypeError` is out of the way: punch out 18:50 on a 18:30 shift -> 20, should be 0. Overnight 22:00-06:00 punched out 06:40 next day -> about 1480 minutes (measured from 06:00 of the *start* day), should be 40. | Shift end anchored on the attendance date (+1 day for overnight); floor minutes; `>= 30` else 0. |
| 17 | `list_attendance` | Loads every matching document into Python, sorts there and slices; `total = len(docs)`. | 100k docs: slow, memory heavy; `COLLSCAN`. | Filter, sort, skip and limit run in MongoDB, backed by indexes; `count_documents` for the total. |
| 18 | `list_attendance` | Sorts by `date` only (contract: date desc, then `emp_code` asc); `page=0` becomes a negative slice; no `page_size` cap. | Same-day rows come back in arbitrary order; page=0 returns the wrong rows. | Sort `(date desc, emp_code asc)`; page/page_size validated (R10). |
| 19 | `list_attendance` | No validation of `status`, `date_from`, `date_to`; `date_from > date_to` not rejected. Leaks `_id` as `id`; returns raw datetimes; legacy documents without `half_day` / `history` are returned incomplete. | `?status=foo`, `?date_from=2026-7-1`, `?date_from=2026-07-09&date_to=2026-07-01`. | `Literal` status, strict date parsing, 422 on reversed range, `serialize_record()` with defaults. |
| 20 | `health` | Always returns ok, even when MongoDB is down. | Stop MongoDB, `GET /health` still 200. | Pings MongoDB, else 503. Also a global handler turns `PyMongoError` into 503, not 500. |

## Looked at and judged fine
- `doc.pop("_id", None)` after `insert_one` in `create_employee`: needed, because PyMongo adds `_id` to the dict it inserts. Kept the idea (I build the response explicitly).
- Pydantic models ignoring unknown fields: this is what the contract wants for derived fields (`work_hours`, `late_minutes`, ... are ignored if a client sends them). Kept.
- `load_dotenv()` without `override=True`: real environment variables already win over `.env`, as required. Kept.
- Defaults `09:30` / `18:30` and the 201 on create/punch-in: match the contract.
- Comparing `date` strings with `$gte` / `$lte`: correct, because `YYYY-MM-DD` sorts as text in date order.
